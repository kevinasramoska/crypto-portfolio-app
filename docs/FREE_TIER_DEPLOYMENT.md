# Free-tier public demo deployment

A portfolio demo, not a production deployment. It uses three free tiers:

| Part | Host | Free-tier behaviour |
|---|---|---|
| Next.js frontend | Vercel | Always on |
| Spring Boot API (Docker) | Render, defined in [`render.yaml`](../render.yaml) | Sleeps after ~15 min idle; first request takes ~1 min to wake |
| PostgreSQL | Neon | 1 GB storage, suspends after 5 min idle, resumes on connect |

```text
Browser ──HTTPS──> Vercel (Next.js) ──HTTPS──> Render (Spring Boot, Docker) ──TLS──> Neon (PostgreSQL)
```

Flyway applies the committed migrations when the API starts, so a new empty Neon database is
initialised by the first deploy. Use only fictional demo data. The [release runbook](RELEASE_RUNBOOK.md)
still applies before any real-user data is stored.

## 1. Database (Neon)

1. Create a Neon project in **AWS Europe (Frankfurt)** (same region as the Render service).
2. Create a database (e.g. `cryptodb`) and copy its connection details.
3. Build the JDBC URL. Neon presents a publicly trusted certificate, so full verification can use
   the JVM trust store:

   ```text
   jdbc:postgresql://<neon-host>/<database>?sslmode=verify-full&sslfactory=org.postgresql.ssl.DefaultJavaSSLFactory
   ```

   Use the **direct** (non-pooler) host: Flyway and the scheduled snapshot job expect a normal session.

## 2. API (Render)

1. In Render choose **New → Blueprint** and select this repository. Render reads `render.yaml`.
2. Enter the `sync: false` values when prompted:
   - `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` from step 1
   - `APP_CORS_ALLOWED_ORIGINS`: set a placeholder now and replace it with the exact Vercel URL after step 3
3. `JWT_SECRET` is generated by Render. Do not copy it anywhere else.
4. Wait for the deploy, then check `https://<render-service>.onrender.com/actuator/health` returns `{"status":"UP"}`.

Render redeploys automatically on every push to `main`. CI (`.github/workflows/ci.yml`) runs on the same push.

## 3. Frontend (Vercel)

1. Import the repository in Vercel and set **Root Directory** to `frontend`.
2. Environment variables:
   - `NEXT_PUBLIC_API_BASE_URL=https://<render-service>.onrender.com/api`
   - `NEXT_PUBLIC_CONTACT_EMAIL=<your contact address>`
3. Deploy, then put the production URL (no trailing slash) into Render's `APP_CORS_ALLOWED_ORIGINS` and redeploy the API.

## 4. Verify before sharing the link

- [ ] `/actuator/health` is `UP`, and other `/actuator/*` endpoints return 401/403
- [ ] Register, sign in, sign out
- [ ] A BUY, partial SELL, edit and delete cycle, with holdings and P&L updating
- [ ] Overselling is rejected
- [ ] A second account cannot see the first account's data
- [ ] Prices load, and CSV export downloads
- [ ] Mobile layout
- [ ] Render logs show Flyway migrations applied with no errors

Add the live URL to the README only after these checks pass.

## Free-tier limits and cost safety

- Expect a ~1 minute cold start on the first visit after the API has been idle. The README says so.
- Do not use external "keep-alive" pings. They consume the free monthly instance hours.
- None of the three services needs a paid plan. If a provider asks you to upgrade, stop and review.
- Neon free projects have no point-in-time restore guarantee; treat the demo database as disposable.
